Full audit done 2026-06-25 (Opus). Build is clean; cardcopy engine verified sound end-to-end (copy/SHA-256/atomic/collision/failure-exit-codes all pass in sandbox). On-disk data is never lost from the card — failed groups don't write the manifest and don't auto-eject, so files re-copy on re-insert.

The real risks are in SIGNALING and CONFIG, not the copy engine:

- **CRITICAL false-success cluster — FIXED 2026-06-25.** Was: `run_ingest` emitted `PHASE done`+`return 0` even on failure; Swift derived "Completed" from a `statusText` substring; stdout reader had no line buffer and dropped throttled chunks (`COPY_ERROR`/`VERIFY_FAIL` not in `isCritical`). Fix shipped: shell now `echo "PHASE failed groups=N verify=M"` + `return 1` on `_failed_groups>0||_verify_failed>0` (CardRunner.sh ~2336); Swift added `IngestPhase.failed`, a `didFail=(exitStatus != 0)||hasCopyError` gate driving status/ring/sound, a "Transfer failed — do not format card" alert, and a buffered newline-split stdout reader + final-drain that never splits/drops error lines. Build passes; buffered reader proven on adversarial 7-byte-chunk input.
- **No source-vs-destination same-volume guard** anywhere (grep st_dev/volumeIdentifier = none) — custom dest / secondary on the source card isn't rejected.
- **Crash-resume gaps:** `IngestCheckpoint` (1288) omits dateOverride/reelFilter/olympics/broadcastDayHour/renameTemplate → resume misroutes wrong-clock/reel/olympics ingests. Launch runs `cleanupOrphanPartialDirs()` (2208, volume-root `rm -rf`, fire-and-forget) BEFORE `checkForStaleCheckpoints()` (2224) → defeats/races resume.
- **History/stats decode** is all-or-nothing (IngestHistoryEntry core fields use non-optional `try decode`; loadHistory `try?` on whole array) → one bad element wipes the audit trail. Presets (262) are the exemplary resilient pattern to copy.
- **Tests: 0% logic coverage** — all three test files are empty Xcode boilerplate (they build & "pass").
- Shell extras: secondary path uses global `${//}` substitution (mangles when PRIMARY_ROOT recurs); scaffold names allow `../` escape; `--latest` flag parsed but never implemented; broadcast-day-hour vs date-filter drops post-midnight clips.
- Release: appcast `sparkle:version` mixes marketing-strings (1.1-1.3) and integers (4-20); `release.sh` build-number via `sort -n|tail -1` is fragile; no `codesign --verify --deep`/`spctl` gate before DMG.

**FIXED 2026-06-25 (same session, all build + tests green):**
- #2 same-volume guard: `volumeDeviceID`/`destinationIsOnCard` (st_dev) now refuses primary/secondary/resume destinations on the source card.
- #8 cancel-queue: Stop still halts all, but now names the queued cards it dropped instead of silently discarding them.
- #3 resume: `IngestCheckpoint.resumeArgs` (optional, back-compat) stores the full arg list; resume replays it verbatim (legacy checkpoints fall back to per-field reconstruction).
- #4 partial cleanup: launch now runs `checkForStaleCheckpoints()` before `cleanupOrphanPartialDirs()`, which skips drives with a pending checkpoint; `discardCheckpoint` cleanup scoped to the project folder not the volume.
- #5 Codable resilience: `LenientDecodable` + `lenientDecodeArray` (one bad row skipped, not whole array) for history/failed-records; `AllTimeStats` resilient `init(from:)`.
- #6 tests: CardRunnerTests now has 6 real passing tests (checkpoint round-trip/legacy, AllTimeStats resilience, history back-compat, preset resilience).
- #7 release.sh: build number read from app target via `-showBuildSettings` + monotonic-vs-appcast guard.
- shell: secondary path now prefix-strip not global `//`; scaffold names reject `/`/`..` escape.

**STILL OPEN:** broadcast-day filter vs date filter (post-midnight clip skip — needs Python scanner edit), proxy `/Proxies` verify path, `--latest` dead flag, unvalidated `--broadcast-day-hour`/`--latest` ints, manifest exFAT-mtime key; #7 leftovers (codesign --deep verify gate, normalize legacy appcast 1.1-1.3 → ints, add minimumSystemVersion). success-determination/parseProgress still need refactor-for-testability.

Most signaling/parse fixes fold into the planned [[the UI revamp]]. See PERF_REVIEW.md for perf items (single-pass scan, coalesced PROGRESS_FILE updates).
